# PraxisCompliance

**Municipal Building Permit Compliance & Pre-Submission Readiness Platform**

PraxisCompliance assists permit applicants and municipal plans examiners by evaluating architectural blueprints against local municipal building codes and zoning ordinances. The platform is **informed by historical correction letters** and **jurisdiction-specific review patterns** to flag common compliance issues prior to formal submission.

> [!IMPORTANT]
> **Governance Notice**: PraxisCompliance calculates an **Approval Readiness Score** and highlights potential code violations for pre-submission remediation. **The system does not approve applications or issue building permits.** Final permit determinations and approvals are made exclusively by authorized human municipal building officials and plans examiners.

---

## Core Capabilities

### 1. Blueprint Evidence on Findings
Every finding generated by the compliance engine traces issues directly to the source:
- **Citation**: Exact section of the municipal code (e.g. `Section 101.2 — Minimum net clear opening width: 20 inches`).
- **Evidence**: Specific parsed blueprint element and dimensions (e.g. `Window W2, basement bedroom (south wall) — parsed net clear opening: 16" × 22"`).

### 2. The Ripple Effect Simulation (Modular Provider Abstraction)
When an applicant resolves one compliance violation by altering a blueprint dimension, adjacent code requirements can be inadvertently impacted. 
- Built upon the `RippleEffectSource` provider abstraction with swappable mock and live implementations (`USE_LIVE_RIPPLE` configuration flag).
- `MockRippleEffectSource`: Provides deterministic results for the basement bedroom renovation demo, resolving egress opening dimensions while surfacing a side yard setback encroachment.
- `LiveRippleEffectSource`: Architecture stub ready to connect to a multi-agent CAD mutation and recheck pipeline.

### 3. Approval Readiness Score
A transparent metric evaluating how well an application satisfies municipal requirements before filing:
- Formula: `100 − (blocking_count × 20) − (advisory_count × 5)`, floored at `0`.
- Includes clear governance labeling: *"Indicates how prepared this submission is for review — not an approval decision. Final determination is made by a human reviewer."*

### 4. Reviewer Decision Support
- Prioritizes pending municipal queues by severity.
- Generates preliminary correction letters and compliance verification notices for reviewer editing and sign-off.
- Tracks reviewer decisions: signed off as-is, edited before sign-off, or rejected.

## Getting Started

Run the development server:

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) to view the application.

### Demo Workflows
- **Applicant Check**: Access `/app?tab=applicant` to check example blueprints or run the Ripple Effect demo on Blueprint B.
- **Reviewer Dashboard**: Access `/app?tab=reviewer` (sign in with reviewer credentials) to manage the submission queue.
